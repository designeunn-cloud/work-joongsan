# 상품평가 스킬

무역부(또는 영업부)가 발굴한 후보 제품들을, 정해진 평가 템플릿 양식에 맞춰 자동으로 평가한다. 내부적으로 서브에이전트 3개(`시장조사` → `분석` → `평가`)를 후보 제품마다 순서대로 돌린다.

## Step 0. 입력 확보

두 파일이 필요하다:
1. **무역부(또는 영업부) 원자료** — 후보 제품 목록(제품명, 단가, 예상원가, 스펙, 있으면 "영업팀 발표 제품" 같은 기존 경쟁 제품 힌트)이 담긴 파일. pptx 또는 xlsx.
2. **평가 템플릿** — 채워야 할 정해진 양식의 xlsx. (예: `202608_상품개발_평가템플릿_영업팀용 (vN)_...xlsx`)

`args`로 두 경로를 안 받았으면, 대화에서 사용자가 언급한 파일을 찾거나 직접 물어본다. 절대 경로를 추측해서 지어내지 않는다.

## Step 1. 두 파일을 읽어서 구조 파악

- **원자료**가 `.pptx`면: `System.IO.Compression.ZipFile`로 원본을 직접 열어(복사본 만들지 말고 원본에서 바로 읽기) `ppt/slides/slide*.xml`의 `a:t` 텍스트 노드를 추출한다. `.xlsx`면 아래와 동일하게 `xlsx` 라이브러리로 읽는다.
- **템플릿**은 `exceljs` 라이브러리로 읽는다 (이 저장소 `node_modules/exceljs`를 그대로 재사용 — 서식·수식 보존이 필요해서 `xlsx` 패키지 대신 이걸 쓴다):
  ```js
  const ExcelJS = require("<repo-root>/node_modules/exceljs");
  const wb = new ExcelJS.Workbook();
  await wb.xlsx.readFile(templatePath);
  ```
  **주의**: exceljs로 읽은 셀 값은 한글+영문이 섞인 텍스트일 경우 `cell.value`가 문자열이 아니라 `{ richText: [{ text: "..." }, ...] }` 형태로 나올 수 있다 (템플릿이 폰트를 글자별로 다르게 지정해서 생김). 텍스트 비교를 할 땐 반드시 `richText` 배열의 `text`를 이어붙여서 비교하고, 순수 문자열이라고 가정하지 않는다.
  평가 시트(이름에 "평가"가 들어간 시트, 보통 유일한 시트)에서 다음을 정확히 뽑아낸다 — **세부질문 목록·대분류·제품 컬럼 헤더를 절대 스스로 지어내거나 기억으로 채우지 말고, 매번 파일에서 새로 읽는다** (템플릿이 버전업되면 문항이 바뀔 수 있음):
  - 대분류 목록과, 각 대분류에 속한 세부질문 텍스트 (No./평가 항목/세부 평가 내용 열)
  - 후보 제품 컬럼들의 정확한 헤더 텍스트와 열 위치
  - "팀원별 한줄 총평" 구역의 행 위치와, "팀원 1" 행 위치
  - (있다면) "팀원점수_입력" 같은 별도 탭 존재 여부 — 있으면 이번 버전에서는 건드리지 않고, 사용자에게 "이 탭은 아직 자동화 대상이 아니에요"라고 짧게 알린다.

  **점수 셀 위치는 반드시 셀 수식(`cell.f`)으로 확인한다, 행 개수로 추측하지 않는다.** "팀 점수(100점 환산)" 셀의 수식을 읽어보면(예: `IF(COUNT(J6,J10,J14,J18,J22)=0,"",AVERAGE(J6,J10,J14,J18,J22)/5*100)`) 실제로 점수가 들어가는 행이 대분류당 정확히 몇 개인지 알 수 있다 — 확인 결과 이 템플릿은 **대분류(No.가 붙은 첫 행)당 점수 셀 1개, 세부질문 4개는 그 점수를 정할 때 참고하는 기준 텍스트일 뿐**이었다(제품 1개당 총 5개 점수, 20개 아님). 버전이 바뀌면 이 구조도 바뀔 수 있으니 매번 수식을 확인해서 다시 판단할 것.

## Step 2. 후보 제품 목록 추출 + 확인

원자료에서 후보 제품 목록(제품명, 단가, 예상원가, 스펙, 경쟁 제품 힌트)을 뽑는다.

**템플릿의 기존 제품 컬럼과 이름을 대조한다.** 원자료의 후보가 템플릿에 이미 컬럼으로 있으면 그 컬럼에 채워 넣을 대상으로 삼는다. 템플릿에 없는 후보가 있으면(예: 새 라운드인데 컬럼이 아직 없음) **새 컬럼을 함부로 추가하지 말고, 사용자에게 몇 개가 컬럼에 없는지 알리고 어떻게 할지 물어본다.**

**후보가 3개를 넘으면(서브에이전트 호출이 많아져 시간이 걸리므로) 진행 전에 사용자에게 "후보 N개, 서브에이전트 총 M회 호출됩니다, 진행할까요?"라고 짧게 확인한다.** 3개 이하면 바로 진행해도 된다.

## Step 3. 후보 제품마다 파이프라인 실행

각 후보 제품에 대해 **순서대로** (서로 다른 후보끼리는 병렬로 돌려도 됨, 다만 한 후보 안에서는 반드시 순서 지킬 것):

1. `시장조사` 서브에이전트 호출 — 후보 제품 정보(제품명, 스펙, 경쟁 제품 힌트) 전달.
2. `분석` 서브에이전트 호출 — 원자료의 해당 후보 정보 + 방금 받은 시장조사 결과 + **Step 1에서 읽은 정확한 세부질문 목록(5개 대분류 × 4개씩, 20개 전부)**을 전달 — 분석 단계는 20개 전부 근거를 다룬다.
3. `평가` 서브에이전트 호출 — 방금 받은 분석 결과(20개 판단) + **5개 대분류 목록(각 대분류의 4개 세부질문도 참고용으로 같이)**을 전달. 이 단계는 **대분류당 1개, 총 5개 점수**로 압축해서 JSON 결과(`scores[]` 5개, `team_total_comment`)를 받는다.

세 서브에이전트 모두 `Agent` 도구로 호출하고(`subagent_type`에 각각 `시장조사`/`분석`/`평가` 지정), 결과를 기다렸다가 다음 단계로 넘긴다.

## Step 4. 결과 파일 조립

`exceljs`로 템플릿을 다시 읽고(Step 1과 동일 방식), 다음을 채운 뒤 새 파일로 저장한다 — **원본 템플릿 파일은 절대 덮어쓰지 않는다.**

1. **평가 시트**: 각 후보의 `scores[]`(대분류당 1개, 5개)를 대분류명으로 매칭해 정확한 셀(대분류 행 × 후보 제품 열)에 점수(0~5)를 채운다 — 세부질문 4개 행(2~4번째 줄)은 건드리지 않는다, 거긴 점수 칸이 아니다. 대분류 합계·팀 점수 셀에 수식이 이미 있으면 절대 덮어쓰지 않는다(수식이 자동 계산하게 둔다 — exceljs는 원본 서식·수식을 그대로 보존하므로 별도 조치 불필요). "팀원 1" 행을 "박지은"으로 값 변경하고, 그 행의 각 후보 제품 열에 `team_total_comment`를 채운다. 팀원2~4·팀장 총평 행은 손대지 않는다.

2. **새 시트 "리서치 분석"** 추가 — **텍스트를 한 줄씩 나열하지 말고, 실제 보고서 레이아웃으로 구성한다** (exceljs로 굵은 글씨·배경색·테두리·병합셀을 실제로 쓸 수 있음, `xlsx` 패키지와 달리 이 서식이 저장 후에도 유지됨). 후보 제품마다 이 구조를 반복:
   - 제목 배너 (진한 배경 + 흰 굵은 글씨, 전체 열 병합): `[제품명] — 리서치 분석 보고서`
   - "핵심 발견" 섹션 배너 + 콜아웃 박스(연한 배경, 굵은 글�스): 시장조사·분석에서 나온 핵심 통찰 한 단락. **조사 과정 서술(예: "2개에서 4개로 늘려보니") 없이 최종 결론만.**
   - (해당되면) "OO 제품과의 동일성 판단" 섹션: 디자인·기능 비교 판단 콜아웃
   - "경쟁 제품 비교" 섹션: 표 형태(제품명 | 판매가 | 정가 | 할인율 | 리뷰수 | 월간구매), 헤더 행은 배경색+굵게, 짝수 행은 옅은 배경(지브라 스트라이프)
   - "평가 근거 상세" 섹션: 대분류마다 소제목 배너 + 표(세부질문 | 판단 및 근거), 긴 텍스트는 `wrapText: true`로 줄바꿈
   - "마진 계산 참고" 섹션: 노란/주황 계열 경고색 콜아웃으로 "채널 수수료는 가정치" 캐비앗을 먼저 띄우고, 그 아래 표(기준 | 가격 | 역산 마진율)
   - 색상 팔레트 예시: 제목 배너 `#1E1B4B`(남색)+흰글씨, 섹션 배너 `#4F46E5`(인디고)+흰글씨, 표 헤더 `#EEF2FF`+진한 인디고 글씨, 경고 콜아웃 `#FEF3C7`+갈색 글씨, 지브라 행 `#FAFAFA`. 열 너비는 내용에 맞게 지정(`worksheet.getColumn(n).width`), 표는 `border`로 셀 테두리를 준다.

3. `await workbook.xlsx.writeFile(outputPath)`로 저장. 저장 후 다시 읽어서 점수·수식·서식이 정상인지 한 번 확인한다.

**저장 위치**: 별도 지정이 없으면 원자료 파일과 같은 폴더에, 템플릿 파일명 패턴을 따라 `[YYYYMM]_상품개발_평가결과_[원자료 브랜드/팀명].xlsx` 형태로 저장한다.

## Step 5. 보고

몇 개 후보를 평가했는지, 저장 경로, 그리고 **점수가 유독 낮거나 "근거 부족"이 많았던 후보가 있으면 짚어서** 사용자에게 요약 보고한다. 서식이 깨졌거나 템플릿에 없던 후보가 있었으면 여기서 같이 알린다.

**마진율 계산 결과를 보고할 때는 항상 "채널 수수료 10~15%는 가정치이며, 실제 수치는 확인이 필요하다"는 캐비앗을 한 줄 붙인다** — 이 자료는 경영진(대표님 등)이 볼 수 있으므로, 가정으로 낸 숫자를 확정된 사실처럼 전달하지 않는다.

**`[낮은 신뢰도]` 태그가 붙은 대분류 점수는 반드시 별도로 모아서 눈에 띄게 보고한다** — "제품이 실제로 별로라 낮은 점수"와 "정보를 못 구해서 낮은 점수"를 사용자가 숫자만 보고 헷갈리지 않게 하기 위함이다. (쿠팡·네이버는 시장조사 단계에서 플레이라이트 스크린샷으로 대부분 자동으로 읽히므로, 이 태그는 그래도 못 찾은 진짜 예외적인 경우에만 남는다.)

## 하지 말 것

- 세부질문·대분류를 템플릿에서 다시 읽지 않고 이전 실행 때 기억으로 채우지 않는다 (템플릿이 바뀔 수 있음).
- 팀원2~4, 팀장 종합 총평 행을 채우지 않는다.
- 원본 템플릿·원자료 파일을 수정하거나 덮어쓰지 않는다 — 항상 새 파일로 저장한다.
- 시장조사에서 확인 못 한 수치를 분석·평가 단계에서 지어내지 않는다.
