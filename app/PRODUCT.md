# Product

## Platform

web

## Users

디자인팀 담당자 1인이 전담 운영한다. 로컬(맥) 환경에서 감시 폴더(watcher)와 웹 대시보드를 함께 실행하며, 엑셀 업무요청서 인테이크부터 업무 등록·진행상황 추적·완료 처리까지 전 과정을 혼자 담당한다. 로그인/인증 시스템이 없고, 단일 운영자가 신뢰된 환경에서 사용하는 것을 전제로 만들어졌다.

## Product Purpose

마케팅팀(상세페이지 요청)·영업부(배너 요청, 플랫폼 다양)·무역부(설명서/패키지 요청) 3개 부서에서 들어오는 엑셀 업무요청서를 자동으로 읽어 담당자·부서·브랜드·제품명·업무요청내용·요청일 등을 해석하고, `날짜_업무요청내용_제품명` 규칙으로 결과 폴더를 자동 생성해 원본 파일을 그 안으로 옮긴다.

예전에는 사람이 엑셀을 직접 읽고 손으로 폴더를 만들고 엑셀/메신저로 진행상황을 공유했다 — 이 수작업 인테이크 과정을 자동화하는 것이 제품의 핵심 가치다. 이후 대시보드(칸반보드/주간 캘린더/업무일지/간트차트)에서 진행상황을 추적하고 완료 처리한다.

## Positioning

엑셀 요청서를 사람이 열어보지 않아도 자동으로 파싱해 결과 폴더까지 만들어주는 인테이크 자동화 도구라는 점이 핵심 메커니즘이다. 일반 프로젝트 관리 툴이나 Notion 자체는 이 로컬 파일시스템 자동화(엑셀 해석 → 폴더 생성 → 파일 이동)를 대신할 수 없다. Notion은 담당자/제품명/플랫폼 마스터데이터의 원천으로 유지하면서, 실제 파일시스템 구조와 진행상황 추적을 하나의 대시보드로 묶는다.

## Operating Context

- "작업" 폴더에 엑셀 업무요청서(.xlsx/.xls/.xlsm)가 들어오면 watcher가 최상위 파일만 감지한다 (자동 생성된 하위 결과 폴더는 재귀 감시하지 않음).
- 해석 모드 2가지: `rules`(무료, 라벨/캐시 매칭 기반, 기본값) / `ai`(Claude API 사용, 유료, 부서마다 다른 양식에 더 잘 대응).
- 필수 항목(담당자/업무요청내용/요청일)을 확신 있게 해석하지 못하면 폴더를 만들지 않고 "확인 필요" 큐(UnprocessedLog)에 사유와 함께 남긴다.
- 해석에 성공하면 결과 폴더 생성 + 원본 파일 이동 + Task 등록(진행중 상태) + 대시보드 노출까지 자동으로 이어진다.
- 담당자/제품명/플랫폼 마스터데이터는 Notion과 동기화한다 (AssigneeCache/ProductCache/PlatformCache). 완료된 업무는 Notion "업무" DB로 단방향 동기화도 가능하다.
- 부가 기능: 연차(Leave) 관리 및 연간 한도 추적, 일일 업무일지(DailyJournal) 스냅샷(자정 기준 전날 고정), 부서×프로젝트 현황과 간트차트.
- `app/performance/page.tsx`(성과)는 아직 실제 기능이 구현되지 않은 스텁이다 ("다음 라운드에서 제공될 예정" 안내만 표시) — 실제 동작하는 기능으로 취급하지 않는다.

## Capabilities and Constraints

- **로컬 단일 머신 실행 유지가 필수 제약이다.** 감시 폴더 접근과 "폴더 열기"(OS 파일 탐색기 오픈) 기능이 로컬 파일시스템에 의존하므로, 클라우드 배포나 외부 접속을 고려한 설계는 불필요하다.
- 로그인/인증 시스템이 없다 — 단일 운영자가 신뢰된 환경에서 사용하는 것을 전제로 설계되어 있다.
- 부서 목록(마케팅팀/영업부/무역부/기타), 브랜드 목록(엑사이더/위즈웰), 수동입력용 플랫폼 목록 일부(쿠팡/스마트스토어/자사몰/기타)가 현재 코드에 하드코딩되어 있다. 이 목록을 확장 가능하게 다뤄야 한다는 요구사항은 아직 확인되지 않았다 (미정 사실로 기록).

## Brand Commitments

현재 제품명/로고/브랜드 컬러 등 시각적 브랜드 자산이 없다. `public/` 폴더에는 Next.js 기본 아이콘만 있고, 페이지 타이틀은 "업무 관리 프로그램"이라는 일반 명칭이다.

## Evidence on Hand

- 실제 데이터 도메인의 근거는 `prisma/schema.prisma`의 Task/Project/Leave/DailyJournal/AssigneeCache 등 모델이다.
- 회사 부서/업무 흐름에 대한 설명은 `lib/interpret.ts`의 AI 프롬프트 주석에 명시되어 있다: 마케팅팀(상세페이지 요청), 영업부(배너 요청, 플랫폼 다양: 네이버/쿠팡/마켓컬리/홈쇼핑 등), 무역부(설명서/패키지 요청).
- 실사용 사례: 2026-08-31에 "위즈웰 네이버 가정의달 쇼핑스토리" 요청서가 실제로 처리되었고, watcher 중복 실행으로 인한 폴더 중복 생성 버그와 그 수정 내역이 `docs/folder-naming-rules.md`에 기록되어 있다.
- 디자인 시안, 스크린샷, 고객 테스트모니얼 등은 없다 — 임의로 만들어내지 않는다.

## Product Principles

1. 수작업 인테이크(엑셀 읽기 → 폴더 생성 → 진행상황 공유)를 자동화하는 것이 제품의 존재 이유다 — 자동 해석·자동 폴더링·자동 상태추적을 항상 우선한다.
2. Notion을 담당자/제품명/플랫폼 마스터데이터의 원천으로 유지한다 — 앱 내부에서 이 데이터를 직접 편집하는 대신 동기화 흐름을 존중한다.
3. 로컬 단일 운영자 환경을 전제로 한다 — 인증/권한/멀티유저 동시성보다, 한 사람이 매일 빠르게 훑고 처리하는 흐름을 우선한다.
4. 확신 없는 자동 해석보다 "확인 필요" 큐로 안전하게 넘기는 쪽을 택한다 — 잘못된 폴더나 데이터를 자동 생성하는 것보다 사람의 확인을 우선한다.
5. 아직 브랜드 정체성이 없는 상태다 — 향후 시각 작업은 백지에서 시작할 수 있지만, 위의 자동화·신뢰·단일 운영자 원칙은 유지되어야 한다.
