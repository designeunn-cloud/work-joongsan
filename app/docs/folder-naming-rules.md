# 결과 폴더 생성 규칙

이 문서는 "작업" 감시 폴더에서 엑셀 요청서가 처리될 때 결과 폴더가 어떤 규칙으로 만들어지는지 정리한 것입니다.

> ⚠️ **이 문서는 설명용 문서일 뿐, 프로그램이 직접 읽지 않습니다.**
> 실제 동작을 바꾸는 것은 아래 "코드 위치"에 적힌 소스 파일입니다. 이 MD 파일의 내용을 고쳐도 프로그램 동작은 전혀 바뀌지 않으며, 규칙을 바꾸려면 해당 코드를 함께 수정해야 합니다. (자세한 내용은 문서 맨 아래 참고)

## 1. 폴더명 형식

```
날짜_업무요청내용_제품명
```

- **제품명이 없으면** 생략되어 `날짜_업무요청내용` 형식이 됩니다.
- 예: `20260831_위즈웰 네이버 가정의달 쇼핑스토리`

## 2. 날짜 규칙

- 폴더명의 날짜는 **엑셀에 적힌 요청일자가 아니라, 폴더가 실제로 만들어지는 시점(처리 당일)** 을 씁니다.
- 형식은 `YYYYMMDD` (예: `20260831`).

## 3. 문자 정리(sanitize)

`업무요청내용`과 `제품명`에는 아래 정리 규칙이 각각 적용됩니다.

1. macOS/공유폴더에서 문제되는 문자 제거: `/ \ : * ? " < > |`
2. 연속된 공백을 공백 1칸으로 축소
3. 앞뒤 공백 제거

## 4. 중복 폴더명 처리

같은 이름의 폴더가 이미 존재하면 뒤에 ` (2)`, ` (3)` ... 을 순서대로 붙여서 충돌을 피합니다.

- 예: `20260831_위즈웰 네이버 가정의달 쇼핑스토리` → 이미 있으면 `20260831_위즈웰 네이버 가정의달 쇼핑스토리 (2)`

⚠️ 다만 watcher가 같은 파일을 중복 처리하는 경합(race)이 생기면 이 로직 때문에 빈 `(2)` 폴더가 남을 수 있습니다 (2026-08-31에 실제로 발생한 사례). 이를 막기 위해 `scripts/watcher.ts`에 PID 기반 단일 인스턴스 락이 추가되어 있습니다 — 같은 감시 폴더를 대상으로 watcher가 두 번째로 뜨면 자동 종료됩니다.

## 5. 처리 흐름 요약

1. "작업" 폴더에 `.xlsx`/`.xls`/`.xlsm` 파일이 들어오면 watcher가 감지합니다.
2. 엑셀 내용을 해석해 담당자·업무요청내용·요청일 등을 추출합니다.
3. 필수 항목(담당자/업무요청내용/요청일)을 확신 있게 해석하지 못하면 폴더를 만들지 않고 "확인 필요" 목록에 남깁니다.
4. 해석에 성공하면 위 규칙대로 폴더명을 만들고, 폴더를 생성한 뒤 원본 엑셀을 그 안으로 옮깁니다.
5. 동시에 DB에 업무(Task)를 등록하고 대시보드에 "진행중" 상태로 표시합니다.

## 코드 위치

| 규칙 | 파일 |
|---|---|
| 폴더명 형식 조합, 문자 정리 | `lib/folderNaming.ts` → `buildFolderName()`, `sanitize()` |
| 중복 폴더명 `(2)`, `(3)` 처리 | `lib/folderNaming.ts` → `resolveUniqueFolderPath()` |
| 위 함수들을 호출해 실제 폴더 생성 + DB 등록 | `lib/taskCreation.ts` → `createTaskFromInterpretResult()` |
| 파일 감지 및 watcher 중복 실행 방지 | `scripts/watcher.ts` |
