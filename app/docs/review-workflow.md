# 업무의 검토 단계

`TaskWorkflowPolicy`의 `review-v1`에 기록된 적용 시점 이후 생성된 업무에 적용한다.
사용자가 요청한 기존 진행 업무는 `review-task:<업무 ID>` 정책으로 개별 적용할 수 있다. 단순 편집이나 완료 업무 재개만으로 자동 전환하지 않는다.

| 업무 상태 | 일지 진행상태 | 실제 완료일 |
| --- | --- | --- |
| 대기 / 진행중 | 대기 / 진행중 | 최초 전달 전에는 비움 |
| 검토 (`submitted`) | 진행중 | 처음 검토로 변경한 날짜 |
| 보류 (`review`) | 보류 | 최초 검토일이 있으면 유지 |
| 완료 | 완료 | 최초 검토일 유지 |

최종 종료는 기존 `endDate`와 `completedAt`에 기록한다. 최초 검토 이후에는 최종 종료일까지 일지에 남으며 날짜별 제외 설정을 존중한다. 코멘트 항목은 변경하지 않는다.

## 배포 시 활성화

마이그레이션은 정책 테이블만 추가한다. 새 코드를 배포하고 데이터베이스를 백업한 뒤, 실제 운영 시작 시점에 아래 쿼리를 한 번 실행한다. ISO UTC 시각을 저장하며 재실행해도 기존 적용 시점은 덮어쓰지 않는다.

```sql
INSERT OR IGNORE INTO TaskWorkflowPolicy (name, activatedAt)
VALUES ('review-v1', strftime('%Y-%m-%dT%H:%M:%fZ', 'now'));
```

정책이 없으면 기존 동작을 유지한다. 활성화 후 `activatedAt`을 변경하거나 정책 행을 삭제하면 업무의 적용 범위가 달라지므로 유지한다. 업무나 기존 일지를 일괄 갱신하지 않는다.

현재 운영 데이터베이스에는 `2026-11-12T00:41:43.339Z`에 활성화했다. 적용 전후 업무·세부할일·일지·시간 기록은 동일함을 확인했다.

## 기존 진행 업무에 적용

사용자가 지정한 진행 업무에 한해 `review-task:<업무 ID>` 이름으로 적용 시점을 저장한다. 원본 업무와 상태 이력은 수정하지 않는다. 적용일 이전 일지는 기존 규칙을 유지하고, 적용 후 사용자가 처음 검토를 선택할 때부터 최초 전달일과 완료까지의 일지 표시를 관리한다. 과거 보류 처리로 기록된 검토 날짜는 새 최초 전달일로 취급하지 않는다.

개별 정책 생성 시 `legacySnapshot`에는 적용 직전 `status`, `reviewDate`, `endDate`, `completedAt` 값을 JSON으로 저장한다. 날짜는 UTC ISO 문자열 또는 null이며, 업무 조회와 정책 삽입은 같은 트랜잭션에서 수행한다. 이를 통해 이후 업무를 완료해도 적용 전 일지의 상태와 날짜 표시를 보존한다.

개별 정책은 완료 이후에도 유지한다. 전체 적용 시점을 과거로 바꾸거나 기존 완료 업무를 일괄 전환해서는 안 된다.
